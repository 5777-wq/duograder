# 内核评估报告 · 种子错误查全率实验 · 2026-10-09

## 实验设计

- 材料：`essay-synthetic-flawed.txt`（135 词英二大作文，**故意预植 12 处已知错误**：10 处 error + 2 处 awkward 级中式直译），种子清单见 `skill/kaoyan-essay/tests/fixtures/planted-errors.json`
- 流程：两位互相不可见的盲评 subagent 按 prompts/v1.0 文件提示词批改 → `eval_planted.py` 与种子清单比对 → rubric 打补丁 → 全新两位盲评员重跑 → 再评估
- 指标：种子查全率（检出/12）、误报候选数（severity=error 但不匹配任何种子）

## 结果

| 内核版本 | 评员 | 查全率 | 漏报 | 误报候选 | 档位判定 |
|---|---|---|---|---|---|
| v1.0（无速查表） | A | 92%（11/12） | ching-grow（grow up better） | 0 | 第四档 10 分 |
| v1.0 | B | 92%（11/12） | ching-grow | 0 | 第四档 10 分 |
| **v1.3（+中式直译速查表 5.1）** | A' | **100%（12/12）** | 无 | 0 | 第三档 9 分 |
| **v1.3** | B' | **100%（12/12）** | 无 | 0 | 第三档 9 分 |

另：ching-situation 在 v1.0 下被两名评员标为 style（期望 awkward），v1.3 下两名评员均按速查表定级 awkward 并显式引用"速查表 5.1 命中"。

## 结论

1. **内核弱点被量化定位**：v1.0 对 awkward 级中式直译存在系统性漏检（两名独立评员同漏同一处，grow up better 甚至被原样保留进修改版）。
2. **rubric v1.3 速查表修复有效**：查全率 92% → 100%，且无新增误报（速查表没有引发过度标记）。
3. **诚实披露**：v1.0 与 v1.3 的档位判定出现漂移（第四档 10 分 → 第三档 9 分）——同一篇作文，内核版本变了分数跟着变。两个档位都在可辩护范围内（该篇本就在三四档边界），但这正说明**缺少人工评分锚点之前，内核版本升级会带动绝对分数漂移**。校准（锚点样文/pairwise）仍是内核最欠的一块，优先级最高。
4. 误报为零是好消息但也可能因为作文太短；种子库需要扩充（更多中式直译变体、更多无辜句），样本量 1 篇×2 评员不构成统计结论。
