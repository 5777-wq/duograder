## 空跑暴露的三个问题与处置

1. **LLM 输出 JSON 缺逗号**（评员 B）：validate_report.py 增加 `}{"` 漏逗号自动修复；结构性更深的损坏走打回重发（本次实际路径），协议允许至多一次。
2. **规则 bug：逐维 .5 向下取整叠加从严偏差**：三次 .5 全部向下（词汇 0.5→0、两处 1.5→1），把 8.5 压到 7。真实阅卷只在总分层面取整一次。**已修 rubric 第 7 节（v1.1）**：维度均值保留 0.25 粒度展示，总分最后取整一次。按 v1.1 规则同一输入应为 8.5 分（3.25+1.5+1.5+0.75+0.5+1 = 8.5，无需取整）。
3. **仲裁 JSON 未过独立校验**：本次仲裁输出未跑 validate（仲裁 schema 尚未落地）→ M2 补仲裁报告 schema + 校验。

# 实验批次二 · 2026-10-08（用户尚无真题作文，先用合成作文跑预注册实验）

## 实验 1：稳定性（预注册验收 #1，合成作文口径）

同一篇带病作文（essay-synthetic-flawed，135 词）双评跑 3 遍：

| 跑次 | 初评 A | 初评 B | 终裁 |
|---|---|---|---|
| 1 | 第三档 8.5 | 第三档 8.5 | 第三档 8.5 |
| 2 | 第三档 8.5 | 第三档 8.5 | 第三档 8.5 |
| 3 | 第三档 8.5 | 第三档 9.0 | 第三档 8.5（维度均值 8.75 收敛） |

**结果：档位波动 0，总分波动 0 —— 通过（合成口径）。** 6 位评员独立评分全部落在第三档，总分极差 0.5 分。

## 实验 2：分档区分度（追加，非预注册）

同题三篇质量递减的合成作文：

| 作文 | 初评 | 终裁 |
|---|---|---|
| good（149 词，无硬伤） | 第五档 14 / 第五档 14 | **第五档 14** |
| flawed（135 词，10 处错误） | 见实验 1 | **第三档 8.5** |
| weak（83 词，55% 字数+错误密集） | 第三档 7 / 第二档 5.5 | **第三档 7**（仲裁采 A） |

**结果：三篇按质量拉开（14 / 8.5 / 7），band 级和分数级都有区分。** 诚实披露：weak 在第二/三档边界存在真实的评分模糊（两位评员各执一词），仲裁员以"错误是否阻碍理解"的事实判断 + 双重惩罚禁止原则裁为第三档低位——边界模糊恰是双评+仲裁机制的设计对象，不是缺陷掩盖。局限：合成作文与评员同源（都是同一宿主模型家族），真实考生的作文待补。

## 首个真仲裁案例实录（weak，档位差 1）

- 分歧：A 第三档 7（锚点"封顶第三档"取低位）vs B 第二档 5.5（错误密度更符合第二档描述）
- 仲裁（pick_a）关键推理：①逐句核验错误全是"透明型"（语义可即时复原），第二档"影响理解"条款不成立；②错误密度已在语法/词汇维度以 0.5/2 计价，再降档属双重惩罚；③锚点结构区分 55%（封顶第三档）与 <50%（封顶第二档），规则本身把该字数段定位在第三档
- 耗时 1 次仲裁调用，rationale 引用档位描述原文，无和稀泥
